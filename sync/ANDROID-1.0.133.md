# Android 1.0.133（138）· 应用内更新与滑动优化

## 本次更新

- “关于 → 检查更新”：正式版 / 试用版渠道，启动每天最多自动检查一次，显示更新说明。点击后才下载，支持进度、取消、重试和服务器支持时的断点续传。
- 下载完成验证 SHA-256，安装前由原生层核对包名、版本和当前应用的签名证书，再交给系统确认安装。不静默安装，也不内置 GitHub 令牌。
- “我的”顶部账号卡片：未登录显示“登录并同步”，登录后显示账号及同步状态；点击卡片或“登录/管理”进入账号页面。
- 小幅边缘横滑更容易翻页：统一短距离与轻甩判断，大屏门槛有上限，支持滑动、覆盖、无动画与滑动直翻；卷页从触点起算。保留上下滚动和长按选字，单次手势不连跳多页。

## 安装与数据

旧版没有应用内更新入口，所以这次仍需手动下载 APK **覆盖安装一次**；不要卸载旧版，不要清除应用数据。包名与此前同步版相同，沿用此前本地证书，现有设置、书架和账号存储不做重置。登录已过期或服务端撤销会话时仍可能需要重登。

多数手机选择 `arm64-v8a.apk`，32 位手机选择 `armeabi-v7a.apk`。覆盖安装若提示签名不一致，请保留旧版和数据并反馈，不要通过卸载解决。

安装后可在“关于 → 检查更新”选择渠道。当前为试用版，默认接收试用版；切到仅正式版后不会提示后续试用更新。尚未发布更高版本时显示“暂无更高版本”是正常情况。

后续发布只要随两个 APK 附上 `android-update.json`，即可在 APP 内检查、下载更新；最后一步仍需要在 Android 系统界面确认安装，首次可能需要允许本应用安装更新。

## 验证与边界

Flutter 静态检查无问题；全量回归 1042 项通过、7 项环境跳过。之后补充缓存失效恢复及分架构版本识别，最终定向复验 80 项通过、1 项环境跳过。Android JVM 22 项通过，包含不同包名、不同签名、降级及版本不匹配的阻止规则。更新清单记录每个 APK 的真实安装版本号：ARM64 为 2138，ARMv7 为 1138，发布基础版本号为 138。

两个 APK 已执行签名、ABI、ZIP/ELF 16 KiB 对齐及打包检查。没有在用户实体设备上执行覆盖升级或系统安装交互，不将单元测试当作真机验收。

网页安装包没有重发，仍在 [网页版同步试用版 Release](https://github.com/zouy3/docleaf-sync/releases/tag/sync-preview-2026-10-25)。
